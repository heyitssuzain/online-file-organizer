Features

Everything that actually works. And what doesn't.

No feature lists written by the marketing department — these are the real behaviors of the organizers, verified against the code and the browsers they run in.

File categorization

Eleven categories — Documents, Images, Videos, Audio, Archives, Code, Executables, Design & 3D, Fonts, Data and Others — using the same extension lists as the desktop AuraFlow app. Extensions are treated case-insensitively (.PDF and .pdf behave identically) and unknown extensions flow into Others rather than being discarded. An extension is a strong hint, not proof: AuraFlow never reads file contents to classify in the plan, and it tells you so.

Three organizing rules

By type — one folder per category (Documents/, Videos/…). By extension — a folder per extension (pdf/, jpg/) with a type parent, handy for big mixed sets. By date — month folders (2025-04/) using each file's last-modified timestamp as your browser reports it — the only reliable date metadata a web page can read.

Batch processing

Select hundreds (or up to 5,000 files) at once. The panel shows totals per category, skipped files (temporary/system), flagged unknown extensions and naming conflicts before anything moves. Scans beyond 5,000 files are capped with a visible warning — a browser tab stays responsive where a desktop app would happily keep going, and the cap is honest about it.

Duplicate detection (content hashing)

Files are grouped by exact size first; only same-size candidates are hashed with SHA-256, streamed in 4 MB slices inside a Web Worker so memory stays flat. Identical content gets flagged even when the filenames differ — and files that merely share a name are never labelled duplicates. Files over 512 MB are excluded with a visible notice.

Conflict-safe naming

Every proposed destination is checked against both the plan itself and — in sort-into-folder mode — the files already in each destination folder. Collisions get the same name_1.ext treatment as the desktop app, step by step, and renamed entries carry a visible badge in the plan. Invalid characters (<>:"/\|?* and control characters) are sanitized so names survive on Windows, macOS and Linux alike.

Plan preview & confirmation

Before anything happens, you see every file, its category and its proposed destination — with counts, total size and conflict badges. Nothing moves until you explicitly choose the destination folder and confirm. That is the same preview-first philosophy the desktop AuraFlow was built on.

Exportable manifests & reports

Every plan and every executed run can be downloaded as JSON (full detail), CSV (auditable table) or a plain-text report. The manifest records original path → destination, category, size, skipped files and every error — enough to explain or manually reverse any change with a normal file manager.

Undo

In sort-into-folder mode (Chromium), every successful move is journaled. One click (or the Undo this run button) moves the latest run's files back to their original places and removes folders that were left empty — mirroring the desktop app's OperationTracker. The undo window is the current tab session: unlike a native app, a browser cannot keep journal promises after you close the page. The manifest remains as a manual fallback.

Exclusions & system hygiene

Temporary (.crdownload, .part, .tmp, .bak…) and system files (Thumbs.db, desktop.ini, .DS_Store…) are skipped by default, exactly like the desktop build, and each skip is visible in the plan rather than silent.

Known limits (stated plainly)

  • A web page sees last-modified dates and sizes — not true creation dates or camera metadata
  • Recursive depth is capped at 3 levels when reading with folder permission
  • Organized ZIPs are stored (uncompressed) and capped at 2 GB of selected files
  • Undo history lives in the tab; closing the page ends it (the manifest survives)
  • Hashing of huge media libraries (many GB) is unnecessary work — size pre-filtering keeps it fast, but a spinning-disk decade-old laptop may still take a while
