How to identify duplicate files — safely

By Suzain · Updated October 2026 · 5 min read

Two files with the same name are usually not duplicates; two files with different names very often are. If that sentence does not immediately make sense, do not run a deduplication tool yet — a wrong dedupe deletes a file you wanted. Here's the thinking, and a safe procedure.

Why names are worthless signals

Files collect name-duplicates in a healthy workflow: invoice.pdf exists in 2026/ and archive/ with different contents (a paid version, a draft version, a template). Meanwhile, true duplicates — the exact same bytes saved twice — wear totally different names: IMG_2047.jpg vs. Copy of IMG_2047.jpg vs. IMG_2047 (1).jpg. Only one of these pairs can be called a duplicate, and its names differ.

The correct algorithm, and why it's safe

  1. Group by exact size. Computing a hash of every file is wasteful — different sizes can never be duplicates. Size is free metadata, so it's the cheap first filter. In practice 90%+ of a typical library is eliminated here.
  2. Hash candidates byte-for-byte. Same size doesn't mean same content, so the remaining candidates are hashed — the standard approach is SHA-256 over the full bytes. A cryptographic hash's collision odds are so astronomically small that, for this purpose, equal hash = equal content.
  3. Stream, don't load. A 4 GB video should not hit RAM. Reading in chunks (4 MB slices) with an incremental hash keeps memory flat regardless of file size — this is how a browser app can hash multi-hundred-MB videos without freezing.

This is exactly what AuraFlow implements: sizes first, SHA-256 only where sizes meet, streamed in a background worker. It's also why it shows a progress count instead of pretending hashing a 300-folder library is instant.

A safe procedure after groups are found

  1. Look before you leap. Open each duplicate group and decide which copy lives. Spa rules of thumb: keep the copy with the more sensible name, keep the one not inside a backup folder, and if in doubt, keep both — disk is cheap, regret is not.
  2. Delete deliberately, small batches. A tool that auto-deletes "all but one" removes your say from the decision. Flagged groups are right; automatic interruptions are wrong.
  3. Recount, then rerun the organizer. Duplicates removed, file counts shrink and the leftover folder sorts cleanly.
Watch out: "similar photos" (same scene, different shots) are not duplicates. Content hashing says nothing about visual similarity — and an organizer that claims to dedupe them is making aesthetic decisions on your behalf. Dedupe means byte-identical; everything else needs your judgment.

What astronomically big files change

Hashing is linear in file size, so enormous libraries take real time. Two honest boundaries many tools set (AuraFlow included): files beyond a ceiling (512 MB in-browser) are skipped with a note rather than grinding the page, and partial files (.crdownload, .part) are excluded — hashing half a download makes a hash of nothing meaningful.

Where desktop and web editions differ

The desktop AuraFlow hashes with the speed of native code; the web edition is within a factor of a few for realistic libraries and imposes practical caps. Both share the essential design: content-based, size-prefiltered, never name-based, never auto-deleting. If you fight a centuries-old archive of 20 GB in a browser tab regularly, use the desktop app for dedup and the web edition for organizing.
